# GUI validation checklist

The native interface needs an interactive Windows desktop. The GUI driver in `tests/gui_smoke.mjs` is separate from CTest and uses the Computer Use API when that runtime is available.

1. Open a plain image, an image with generation settings, and a malformed fixture generated by `tests/make_fixtures.py`.
2. Check that Simple is the default and highlights useful evidence, with warnings visible and missing information labeled honestly.
3. Switch to Detailed and inspect Metadata, Structure, Hex and Provenance. Switch back without rescanning.
4. Filter and search findings, select rows, and check readable details and Copy.
5. Export a full report from Simple; confirm that raw fields and blocks are retained and local-path redaction is applied when selected.
6. Resize the window and check text clipping, wrapping, scrolling, keyboard focus and control visibility.

The 0.3.0 release passed all three local automated suites. Simple was visually checked on a real Gemini PNG. The final automated view-switch check was incomplete; this checklist describes additional verification to perform, not checks claimed as completed.

## 0.4.0 validation

All four automated suites passed on Windows x64: engine (99 assertions), provenance (41), presentation (14) and photo/capture (61, including the local real Canon sample). The photo suite checks generated JPEG, PNG and metadata-only TIFF files, XMP-only/conflicting models, source preservation, missing/unavailable extraction, capture timestamps/settings, zero GPS coordinates, serial numbers, exports and unchanged originals.

The interactive 0.4 GUI check was stopped with the physical Escape key before a window could be inspected. No completed visual or view-switch validation is claimed for this version. Remaining interactive checks: open `camera.png`, `camera-conflict.png`, `clean.png` and a real photo; select camera/lens/GPS findings; switch Simple/Detailed; filter Photo / device; search for the model; copy and export; resize and inspect wrapping/clipping.

## 0.5.0 validation

Five automated suites pass: engine (99 assertions), provenance (41), presentation (14), photo/capture (61) and origin/privacy (39). Origin/privacy tests cover camera/AI signals, absent evidence, original source links, independent omission groups, structured contact metadata, raw/duplicate payload exclusion, unperformed validation, all three export formats, preserved errors/cancellation counts and unchanged full evidence/original bytes.

On Windows x64 at approximately 1240 x 800, the real 0.5 application was launched with the generated camera PNG. Simple showed origin, privacy and capture findings. Switching to Detailed, searching for Origin summary, and returning to Simple worked without rescanning. The native share dialog showed all three omission choices checked, with readable limits and buttons. A JSON share summary was exported through the actual dialog/Save flow; a separate file-content check confirmed the selected GPS/serial fields and local paths were omitted. The privacy finding label was shortened after observing clipping in its table column.

Local evidence: `tests/output/ui-0.5-simple.jpg` and `tests/output/gui-share-summary-0.5.json` (excluded from the repository). Keyboard navigation was used for the standard Save dialog because targeting its nested controls through accessibility was unreliable. Pointer-only file dialogs, min-size resizing, copy, multi-monitor/high-DPI combinations and every omission-checkbox combination were not all exercised interactively; omission combinations are covered by automated tests.
